# Budget Tracker CLI — все домашние задания по TypeScript

Выполнены все 13 этапов из [репозитория преподавателя](https://github.com/vovachebr/TypeScript-homeworks). Итог — консольное приложение для учёта личных финансов с интерактивным меню на Inquirer. [Указатель по заданиям и решениям](HOMEWORKS.md) содержит ссылки на условия, файлы и команды запуска.

## Установка и запуск

Нужны **Node.js 22.13 или новее** и npm.

```bash
git clone https://github.com/MagEk1511/ts-hse-homework.git
cd ts-hse-homework
npm ci
npm start
```

Запуск с двумя счетами и семью транзакциями из условия итоговой работы:

```bash
npm start -- --demo
```

Стрелки выбирают пункт, Enter подтверждает выбор, Ctrl+C завершает работу. В меню можно создавать, просматривать, переименовывать и удалять счета, добавлять, редактировать и удалять транзакции, экспортировать историю в CSV. Перед удалением и перезаписью существующего CSV запрашивается подтверждение. После действия программа возвращается в соответствующее меню.

По умолчанию дата новой операции — текущий день. Можно вводить суммы с точкой или запятой; принимаются положительные суммы с точностью до копеек и существующие даты `YYYY-MM-DD`. Пустые названия счетов отклоняются. Ошибки операций выводятся в консоль, меню продолжает работу.

**Данные хранятся в памяти до выхода.** Экспорт сохраняет выбранный счёт в `exports/<имя>.csv`; файлы экспорта не попадают в Git. Загрузка данных и долговременное хранение условиями курса не предусмотрены.

## Сборка и проверки

```bash
npm run build             # Чистая сборка основного проекта в dist/
npm run typecheck         # Строгая проверка проекта и тестов типов
npm run build:examples    # Сборка отдельных этапов 4 и 7
npm test                  # Сборка, типы, примеры и автоматические тесты
npm run dev               # Перекомпиляция при изменении файлов
npm run start:compiled -- --demo  # Запуск собранного приложения
```

`npm start` использует `tsx`, как в задании 8. Компиляция также работает независимо от `tsx`. Примеры 4 и 7 собираются после основного проекта, поскольку чистая сборка удаляет содержимое `dist/`.

Проверено: установка через `npm ci`, 45 автоматических тестов, положительные и отрицательные проверки типов, все учебные примеры и настоящий интерфейс Inquirer в обоих режимах запуска. CSV дополнительно проверен независимым парсером.

## Учебные примеры

```bash
npm run demo:all          # Все неинтерактивные примеры, включая этапы 4 и 7
npm run demo:calculations # Базовые вычисления
npm run demo:functions    # Пять функций для анализа бюджета
npm run demo:interfaces   # Объектная реализация без классов, числовые ID
npm run demo:oop          # Классы, сводки, поиск и удаление
npm run demo:generics     # GenericStorage<Product> и объект без describe()
npm run demo:namespaces  # Общий namespace BudgetTracker, сборка в один файл
npm run demo:types       # Utility, conditional и mapped types
npm run demo:decorators  # Логи, запрет изменения ID и метаданные
npm run demo:csv         # Асинхронный экспорт в exports/demo.csv
```

Декораторы применены в основных классах. Чтобы показать их логи во время работы меню, используйте `npm start -- --demo --logs`. В обычном режиме меню логи отключены, как допускает итоговое задание.

## Решения при переходе между этапами

Задания накопительные: поздние требования заменяют некоторые ранние. В итоговом приложении числовые ID заменены автоматически генерируемыми UUID, а монолитные `classes.ts` и `types.ts` — отдельными ES-модулями. В самостоятельных примерах 4 и 7 сохранены ранние варианты с числовыми ID. Первоначальная версия классов темы 5 доступна в [истории репозитория](https://github.com/MagEk1511/ts-hse-homework/tree/ab216e1ab26a10f28fc9cb7d03ffb3647302334a).

Для задания 7 используется отдельная конфигурация с `module: none` и `outFile`; основная конфигурация работает с ES-модулями `NodeNext`. Закреплён TypeScript 5.9.3: он поддерживает требуемый учебный режим `outFile`, удалённый из TypeScript 7.

UUID и Moment имеют собственные декларации; Lodash используется с `@types/lodash`. Собственная JavaScript-библиотека импортируется по относительному пути, поэтому её `.d.ts` и выполнение в Node работают без несуществующего npm-модуля или отдельного загрузчика псевдонимов.

В типах обновлений ID исключены: транзакция может менять сумму, тип, дату и описание, счёт — название. Обновление сначала проверяет все поля, затем изменяет состояние. UUID защищены декоратором `ReadOnly` и во время выполнения. Название остаётся редактируемым согласно этапу 9 и назначению итогового контроллера.

Списки хранятся в приватных полях; наружу выдаются копии массивов. Суммы складываются в целых копейках. `getSummary()` возвращает `{ income, expenses, balance }`, текстовые методы показывают названия и историю операций. CSV имеет заголовок `id,amount,type,date,description`; кавычки удваиваются, значения со спецсимволами заключаются в двойные кавычки.
